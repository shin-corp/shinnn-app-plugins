# 初回セッション

アプリ用の空のフォルダから始めて、**当社担当と一緒に 60 分**で行う手順です。
この 60 分で「1 つ作って提出して取り込む」までを一通り体験します。

## 事前に用意するもの（顧客側、当日までに）

| もの          | 確認の仕方                                                                    |
| :------------ | :---------------------------------------------------------------------------- |
| Node.js 24 系 | `node -v`（24.15 以上）                                                       |
| npm 11 系     | `npm -v`（Node.js 24 に同梱）                                                 |
| Git           | `git --version`                                                               |
| GitHub CLI    | `gh --version` と `gh auth status`                                            |
| GitHub の権限 | 自社の置き場所（組織か自分のアカウント）にリポジトリを作れること              |
| Claude Code   | 起動できること                                                                |
| Docker        | 任意。無くても進められます（Docker Desktop でも WSL の Docker Engine でも可） |

## 進め方

### 1. フォルダとプラグインを用意する（5 分・当社担当と一緒に）

1. アプリ用の空のフォルダを作ります。フォルダ名が GitHub のリポジトリ名の既定になります
2. ターミナルでそのフォルダに移り、当社のプラグインを入れて Claude Code を起動します

   ```sh
   claude plugin marketplace add shin-corp/shinnn-app-plugins
   claude plugin install shinnn-app@shinnn --scope project
   claude
   ```

3. フォルダの信頼を聞かれたら承認します

### 2. テンプレートを展開する（5 分・当社担当と一緒に）

```
/shinnn-app:setup
```

フォルダが空なので、setup はまずプラグインに同梱されたテンプレートを展開します。

1. 展開する版とファイル数が表示されるので、確認して進めます
2. git のリポジトリを作り、最初のコミットをします
3. GitHub にリポジトリを作ります。置き場所（組織かアカウント）と名前を聞かれます（非公開で作ります）
4. 起動し直すよう案内されたら、`/exit` で終了し、**同じフォルダで** `claude` を起動し直します。
   規約は起動時に読み込まれるためです。以降も**必ずこのフォルダ（リポジトリの一番上）で起動してください**
   （下のフォルダで起動すると、規約が読み込まれません）

### 3. セットアップ（20 分・当社担当と一緒に）

起動し直したら、もう一度実行します。

```
/shinnn-app:setup
```

順番に次を決めます。分からない項目は既定のまま Enter で進めて構いません。

1. **テンプレートの種類**（`full` = 画面とサーバー / `client-only` = 画面だけ）
   - `client-only` はまだ自動で適用されません。この場で終わらない作業になるため、
     **初回は `full` のまま進めます**（`client-only` が要る場合は当社担当が別途手で適用します）
2. **環境の確認** — Node・npm・Git・GitHub CLI・Docker があるかを自動で調べます
3. **データベースの用意方法** — この場で決めて、動くところまで確認します
4. **必須の設定**（外せません）— 「なぜ必須か」を 1 行ずつ説明します
5. **選べる設定** — 費用がかかるものは、目安と「入れない場合に何が起きるか」を示します
6. **当社担当のアカウント** — レビューの割り当てに使い、リポジトリに招待します

決めた内容は、setup が作業票（Issue）を作ってから変更し、提出（PR）にまとめます。`main` に直接は入れません。
取り込むと、`README.md` の「有効な機能」表と `docs/decisions/0004-setup.md` に、決めた内容が残ります。
取り込み（マージ）は、既定では当社担当がその場で行います。

### 4. 動かしてみる（5 分）

```sh
npm install
npm run dev
```

サンプルの `item` の API は認証が要ります。ログイン画面はテンプレートに含めていないので、
**最初に通行証（JWT）を 1 つ発行して画面に持たせます**（別のターミナルで実行します）。

```sh
npm run token -w server
```

出てきた値を、ブラウザの開発者ツールのコンソールに入れて画面を再読み込みします。

```js
localStorage.setItem('token', '<発行された値>');
```

これでサンプルの `item` の一覧・登録・編集・削除が動くことを確認します。
入れずに開くと一覧が `認証されていません。（APP_UNAUTHORIZED）` になります。

### 5. 規約を 1 つ聞いてみる（5 分）

```
/shinnn-app:why architecture
```

「なぜフォルダの種類を増やさないのか」が、やさしい言葉と例で表示されます。
**この体験が目的です。**規約を暗記する必要はなく、いつでも聞けることを確認してください。

### 6. 最初の機能を作る（15 分）

```
/shinnn-app:feature "このアプリの目的と、最初に作りたい画面"
```

Claude が 3 つまで質問をして、`docs/仕様書.md` の目的・画面・**完成の条件（AC-n）**を埋め、
作業票（Issue）を作り、ブランチを切って実装まで進めます。

```
/shinnn-app:check
```

型の検査・書き方の検査・テストが走ります。赤い表示が出たら、そのまま Claude に貼り付けて直します。

```
/shinnn-app:pr
```

変更が提出（PR）されます。GitHub の画面を開き、次を一緒に確認します。

- CI（自動の検査）が緑になること
- 本文に `Closes #<作業票の番号>` と書かれていること
- 変更されたファイルが、上で決めた場所に収まっていること

### 7. 取り込む（5 分・当社担当）

当社担当がレビューしてマージします。マージすると次が自動で起きます。

- 作業票（Issue）が閉じます
- `docs/progress.md` が作り直されます

**ここまでが 1 周です。**明日からは `feature` → `check` → `pr` を繰り返します。
作りたいことが複数あれば、まとめて `feature` に伝えます。分け方と作る順番は Claude が決めます。

## 終わったら

```
/shinnn-app:retro
```

今日の学びが作業票にコメントとして残ります。
