# コーディング規約（server）（規約 `server-coding-conventions.md`）の理由

利用者ごとのデータの決まりを置くのは、ログインしただけの利用者に、他人のデータを扱わせないためです。ログインして
いるか（認証）と、そのデータを扱ってよいか（認可）は、別の確認です。`isAuthenticated()` は、ログインしているか
だけを見ます。

持ち主で絞るのを service のすべての条件に求めるのは、他人のデータに届く経路を残さないためです。id だけで絞る
書き方は、最もよくある誤りです。しかも、テストで気づきにくい誤りです。自分のデータだけで試すと、他人のデータに届く
経路があっても、全部のテストが通ります。id は URL や画面に出ます。そのため、id を書き換えて他人のデータを開く攻撃は、
特別な道具なしでできます。

他人のデータを 403 にしないのは、その id のデータがあることを知らせないためです。403 は「データはあるが、扱えない」
という意味になります。一意性を全体で判定しないのも、同じ理由です。全体で判定すると、409 から、他人のデータがある
ことが分かります。

ルートを `route()` で定義するのは、検証を通していない値が DB まで届く経路を無くすためです。`route()` は、handler の
直前で入力を検証し、`req.params` / `req.query` / `req.body` を検証後の値に置き換えます。そのため、検証を書き忘れた
エンドポイントは作れません。

1 つのルートだけに掛ける middleware を `route()` に並べるのは、`router.post(...)` を直接書かずに済ませるためです。
直接書いたルートは、API 定義の検証を通りません。`route()` は、並べた middleware の後で入力を検証します。そのため、
middleware が `req.body` を作る場合（ファイルを含むフォームの本文の受け取りなど）も、`req.body` に入るのは検証を
通った値です。

API 定義に無いルートを作らないのは、すべてのルートを CI の API 定義の検査に掛けるためです。この検査は、API 定義に
あるルートだけを数えます。API 定義に無いルートは、テストが無くても CI が通ります。

handler に `RouteHandler<...>` の型を付けるのは、API 定義と handler の食い違いをビルドエラーにするためです。
型を付けると、`req.params` / `req.query` / `req.body` の型と、`res.json()` に渡せる値の型が API 定義から決まります。
API 定義に無い部分は `unknown` 型になります。そのため、検証していない値は、そのままでは読めません。

成功したときのステータスを使い分けるのは、レスポンスの意味を実際の処理と合わせるためです。201 は「作成した」という
意味です。作成ではない POST（検索・ログインなど）に 201 を返すと、意味が処理と食い違います。

本文を返さないルートで 204 を返すのは、画面の `call()` が本文を読み損なわないようにするためです。`call()` は、204 の
ときだけ本文を読みません。204 以外のステータスで本文が無いと、`call()` は無い本文を JSON として読もうとして失敗します。

`/health` を API 定義に入れないのは、監視の呼び出しを rate limit で止めないためです。API 定義のルートは `/api` の
下に置かれ、rate limit が掛かります。

`details` に内部の情報を入れないのは、攻撃の手がかりを利用者に見せないためです。`details` は、文言と一緒に
レスポンスで画面へ返ります。

サーバーのテストが受け取るレスポンスの本文は、API 定義で形が決まっています。そのため、テストでは検証せずに型を
付けてよいとしています。

`process.env` を 1 か所に集めるのは、設定漏れを**起動時**に見つけるためです。読む箇所が散らばっていると、設定漏れに
気づくのは、特定の画面を開いて `undefined` が出たときになります。接続先や秘密の値に `default()` を付けないのも、
同じ理由です。付けると、本番で設定を忘れても起動してしまいます。

`console` を禁じる理由は 2 つあります。1 つ目は、ログの出力先と書式をそろえるためです。2 つ目は、`console.log` が
本番に残り、個人情報を出し続けるのを防ぐためです。

Express 5 の 8 項目を明示するのは、Claude が Express 4 の書き方で書くのを防ぐためです。Claude の学習データには、
Express 4 の書き方が大量にあります。4 の書き方は、5 ではそのままでは動きません。
