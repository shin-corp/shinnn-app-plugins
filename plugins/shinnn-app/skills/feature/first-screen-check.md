## 10. 最初の画面を確かめてもらう（`auto-merge`）

1. 画面を撮る。`/shinnn-app:dev-stack-start` で起動し、`add-screen` の「9. 作った画面を見直す」の 1 の形で、作った画面を `screenshots/` に撮る。
   作り直しでは、元の画像がある画面だけ、元と新を並べた画像も作る（`add-screen` の「作り直しのとき」）。画面が無いときは撮らない。
   撮れない（ブラウザが無い、スクリプトが止まる）ときは、撮らずに 2 に進み、3 では画面の開き方だけを伝える
2. Issue を作る。題は `[確認] 最初の画面の確認`、ラベルは `type:feature` と `status:doing`、本文の先頭に `計画: #<親の番号>` を書く。本文には次を書く
   - 計画の一覧（親 Issue の「作る順番」と「今回やらないこと」）。作り直しでは、移植対応表の場所と、「まだ」の件数と全体の件数
   - 撮った画像の置き場所。リポジトリからの相対パスで書く（絶対パスには利用者の名前が入りうる）。
     例: 並べた画像は `screenshots/compare/<画面の名前>.png`、元の画像が無い画面は `screenshots/<画面の名前>.png`。
     画面が無いときは、代わりに、できたこと（使う人から見て何ができるようになったか）と、その確かめ方を書く
   - 確かめてほしいこと（配置・色・項目・言葉）。作り直しでは、移植対応表の「違う」の行と「違い」の列も見てほしいこと（表の場所を添える）
   - 作り直しで、見せる画面に元の画像が無ければ、そのことと、元のアプリのコードから作ったこと
3. 利用者に、2 の中身を利用者の言葉で報告して止まる。報告には、画面の開き方と、次の 2 つを添える（画面が無いときは、画面の開き方は添えない）
   - 直したいところがあれば伝えてほしいこと
   - このままでよければ「続きをお願いします」と伝えてほしいこと
4. 返事を受けたら、次を順に行う
   1. 直したいことがあれば、計画の中の Issue に足すか、`plan.md` の「計画に足す」で Issue にする。作り直しでは、移植対応表の行も直す
   2. 返事の要点を `[確認]` の Issue にコメントして閉じる（`gh issue close <番号> --comment "<要点>"`）
   3. 「続きから始める」の 1 の後半（待っている PR への `main` の取り込み）から続け、進められる Issue が無くなるまで作りきる
