# コミット前の確認

コミットの直前に、`pre-commit` フックと同じかそれ以上を手元で通す。

## 実行する順

| 順 | 内容 | コマンド |
|:--|:--|:--|
| 1 | 変更ファイルの確認 | `git -c core.quotepath=false status --short` |
| 2 | ビルドと型検査 | `npm run check` |
| 3 | 変更範囲のテスト | `npm test`（範囲を絞るなら `npm run build` の後に `npm run test -w <変更したパッケージ>`） |
| 4 | 改行コードだけの差分が無いこと | `git diff --shortstat` と `git diff --ignore-cr-at-eol --shortstat` の一致 |
| 5 | 意図しないファイルが混ざっていないこと | `.env`・生成物・一時ファイル・実データが `git status` に出ていないか |

## コミット内容の確認

- **`.claude/rules/git-workflow.md` の「コミットの分け方」（例外を含む）に反していないか**（層をまたぐ変更、実装とテストの混在）
- ルートの `CLAUDE.md` の「共通方針」のとおり、挙動を説明しているコメントと JSDoc が実装に合っているか

## 落ちたとき

- 直してから再度この手順を最初から通す。**一部だけ通し直さない**
- フックを飛ばさない（`.claude/rules/git-workflow.md` の「やらないこと」）

## 報告

```
コミット前確認: OK / NG
対象ファイル: N 件
NG の場合: 落ちた項目と直し方
```

このスキルは確かめるだけで、コミットはしない（コミットは `feature`・`pr` の手順の中か、人に頼まれたときに行う）。
