# 0003. Node.js は 24 LTS を前提にする

- 状態: 決定
- 日付: 2026-09-08

> **設計判断の記録（ADR）とは** 「なぜそう決めたか」を 1 件 1 ファイルで残し、後から来た人が
> 「これは変えてよい判断か」を自分で判断できるようにするための文書です。

## 背景

[0002](./0002-package-manager.md) で「Node.js を入れれば動く」ことを重く見て npm を選びました。
npm は Node.js に同梱されるので、Node.js の版を決めることが npm の版を決めることになります。
選ぶ版は次を満たす必要があります。

1. **LTS であること** — 顧客のリポジトリは数年使われる
2. **Angular 22 の要求を満たすこと** — Angular 22 の `engines` は `^22.22.3 || ^24.15.0 || >=26.0.0`
3. **同梱の npm で、このテンプレートの依存がそのまま入ること** — npm を別に上げてもらわない

## 決めたこと

**Node.js 24 LTS を前提にする。** ルートの `package.json` の `engines` は次のとおりです。

```json
"engines": {
  "node": ">=24.15 <25"
}
```

- **`npm` の指定は書きません。** Node.js 24 は npm 11 系を同梱するので、Node.js の版を縛れば
  npm の版も決まります。`.npmrc` の `engine-strict=true` により、版が足りなければ
  `npm install` / `npm ci` がその場で止まります
- **下限が 24.15 なのは Angular 22 の要求です。** 24 系では 24.15 以上しか受け付けません
- 上限を `<25` にしているのは、奇数番の版が LTS にならないためです。次の LTS は 26 系です

### 実測

Node.js 24.20.0（同梱 npm 11.19.0）で、CI が走らせるものと同じ手順を通しました。すべて exit 0 です。

| 手順                                                                                                                                    | 結果             |
| :-------------------------------------------------------------------------------------------------------------------------------------- | :--------------- |
| `npm ci`（`node_modules` を消してから）                                                                                                 | 約 25 秒         |
| `npm run check`（ビルド + 型検査 + lint）                                                                                               | 約 23 秒         |
| `npm test`                                                                                                                              | 73 件すべて通過  |
| `npm audit --audit-level=high`                                                                                                          | high 以上は 0 件 |
| 規約チェック 5 本（`check-mandatory` / `check-test-naming` / `check-ac-coverage` / `check-api-coverage` / `progress-snapshot --check`） | すべて通過       |

Node.js の版に起因する警告（非対応 API の通知や `engines` の不一致）は出ません。

## Node.js 22 を選ばない理由

22 系も LTS で、Angular 22 の要求も満たします。それでも選ばないのは、**同梱の npm 10 系では
新しい依存の解決に失敗することがある**ためです。たとえばテストで使う Vitest 4.1 系は、npm 10 では
peer 依存の解決で異常終了します（`Cannot read properties of null (reading 'edgesOut')`）。
回避するには npm 11 系を手で入れてもらうしかなく、それは「Node.js を入れれば動く」を
成り立たせません。手元では `npm install` が `EBADENGINE` で止まってから「npm を上げる」と
気づく順番になり、CI にも「npm を上げる」ステップが要ります。

依存を足すたびに同じ落とし穴を踏む可能性が残るより、**同梱の組み合わせのまま動く版を選ぶ**方が、
開発に慣れていない担当者の手元では確実です。

## 結果

- 手元で必要なのは Node.js 24 系（24.15 以上）だけです。npm は同梱のものをそのまま使います
- CI（`.github/workflows/ci.yaml`）の `NODE_VERSION` は `'24'` です
- `server` の `@types/node` は 24 系です（実行する Node.js と型の版をそろえるため）

## 見直す時期

- Node.js 26 系が LTS になったとき（2027 年 10 月の予定）。Angular が対応した時点で上げます
- Angular が `engines` の下限を上げたとき。`>=24.15` の数字もそれに合わせます
