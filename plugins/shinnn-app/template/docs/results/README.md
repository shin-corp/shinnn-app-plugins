# 手で確かめた結果

自動テストでは確かめられないものについて、**実際に動かして確かめた結果**をここへ残します。
受入条件（AC-n）は自動テストで確かめ、CI が対応を照合します。そのため、ここには書きません。

## ここに残すもの

- 規約が手元での確認を求めているもの（例: `.claude/rules/ai-integration.md` の「評価」の結果。書く項目はその規約に従います）。引き継ぎの条件です
- そのほか、テストでは差し替えている外部のサービスに、実際につないで確かめたこと（任意）

## ファイルの作り方

- 確かめた対象ごとに 1 ファイル。ファイル名は対象が分かる英小文字にします（例: AI の評価は `<機能>-eval.md`、メールの送信は `provider-mail.md`）
- 同じ対象を確かめ直したら、同じファイルを書き換えます
- 引き継ぎのとき、シン株式会社はこのディレクトリを見て「自動テストの外をどこまで確かめたか」を判断します

## 書き方の雛形

```markdown
# メールの送信が届く

- 確認日: 2026-09-06
- 確認した人:
- 確認した版: <コミットのハッシュ、または PR 番号>

## 確認したこと

<!-- 何をして、何が起きたか。手順が分かるように書きます。 -->

## 結果

<!-- 期待どおりだったか。違ったならどこが違ったか。 -->

## 残っている懸念

<!-- 気になっているが今回は扱わないこと。無ければ「なし」。 -->
```

## 画像を貼る場合

- 画面の写しは同じディレクトリに置き、Markdown から相対パスで参照します
- **実際の業務データが写った画像を置かないでください。** テスト用のデータで撮り直します
- 1 MB を超えるファイルを git に入れないでください
