# shinnn-app-starter

アプリを作りはじめるためのスケルトンです。画面（client）・サーバー（server）・両者が共有する API 定義（shared）が
最初から動く形で入っています。サンプルとして `item` の一覧・登録・更新・削除がひととおり実装してあるので、
これを真似て自分のアプリの機能を足していきます。

**プログラミングに詳しくない方は、まず [docs/アプリ作り方ガイド.md](docs/アプリ作り方ガイド.md)（2 ページ）を読んでください。**
ここから下は、コードを直接触る人向けの説明です。

- **API 定義**: 画面とサーバーがやり取りするデータの形（URL・入力・出力）を `shared` に 1 か所だけ書いたもの。
  両側が同じ定義を参照するので、片方を変えるともう片方がビルドエラーになり、書き写しによる食い違いが起きません。
- **ワークスペース**: 1 つのリポジトリに複数のパッケージ（client / server / shared）を置いて、まとめて扱う仕組みです。

## 必要なもの

| もの       | 版                                           |
| ---------- | -------------------------------------------- |
| Node.js    | 24 系（24.15 以上）                          |
| npm        | 11 系（Node.js 24 に同梱）                   |
| PostgreSQL | 16（用意の仕方は下の「データベースの起動」） |

npm は Node.js に同梱されるものをそのまま使います。別に入れるものはありません
（理由は `docs/decisions/0003-node-version.md`）。
版が足りないときは `npm install` がその場で止まるので、気づかないまま進むことはありません。
他の案件で Node.js 22 系を使い続ける必要があるなら、Volta や nvm（版を切り替える道具）で案件ごとに切り替えてください。

## 3 つのコマンド

```sh
npm install    # 依存をそろえる（初回のみ）
npm run dev    # 起動する（画面とサーバーを同時に立ち上げる）
npm test       # テストする
```

`dev` / `test` / `check` は、先に `shared`（API 定義）をビルドしてから走ります。

デプロイは `npm run build` で成果物を作ってから配置します。手順は `docs/env.md` を参照してください。

品質チェックは `npm run check`（型検査 + lint）です。コミット時には、コミットするファイルの lint と整形が自動で走ります。コミットメッセージの形も確かめます。型検査とテストは CI が確かめます。

## 画面から API を呼ぶための通行証（開発中）

サンプルの `item` の API は認証が要ります。認証のやり方はアプリごとに違うので、ログイン画面はテンプレートに含めていません。
そのため、**開発中は通行証（JWT）を手で 1 つ発行して使います**。

```sh
npm run token -w server
```

出てきた値をブラウザの開発者ツールのコンソールに入れて、画面を再読み込みします。

```js
localStorage.setItem('token', '<発行された値>');
```

これをしないと一覧が `認証されていません。（APP_UNAUTHORIZED）` になります。
発行には `server/.env` の `JWT_SECRET` と `JWT_AUDIENCE` が必要です（`server/.env.example` が雛形）。
データベースを PGlite にしたときは、`/shinnn-app:setup` が `server/.env` を作ります（`JWT_SECRET` にはランダムな値が入ります）。
**本番では使いません。** ログイン API を作ったら、そちらが発行した値を入れる形に置き換えます。

## データベースの起動

PostgreSQL の用意の仕方は、`/shinnn-app:setup` でこのパソコンを調べてから選びます。
選んだ方式と、起動と停止の手順は、`docs/env.md` の「ローカルの PostgreSQL」節にあります。

- Docker: `docker compose --profile dev up -d` で立ち上げます
- このパソコンで動いている PostgreSQL: そのまま使います
- PGlite（API サーバーの中で動く PostgreSQL）: 入れるものも、別に立ち上げるものもありません。`server/.env` は `/shinnn-app:setup` が作ります。本番では使いません。PostgreSQL 16 とは版が違うので、本番の前に 16 で動作を確かめます
- マネージドの PostgreSQL（提供元が動かす PostgreSQL。Neon などの無料枠）: 接続先を `server/.env` の `DATABASE_URL` に書きます

## リポジトリの構成

| 場所       | 中身                                                                                                              |
| ---------- | ----------------------------------------------------------------------------------------------------------------- |
| `shared/`  | 画面とサーバーが共有する API 定義（zod スキーマ）。業務ロジックは置かない                                         |
| `server/`  | Express 5 のサーバー。`api/` → `service/` → `db/` の順に呼ぶ                                                      |
| `client/`  | Angular の画面。API 呼び出しは `api-client.ts` の `call()` だけを使う                                             |
| `docs/`    | 仕様書・環境変数・設計判断の記録                                                                                  |
| `.claude/` | Claude Code の設定とルール（権限の設定と規約はシン株式会社が配る標準で、`/shinnn-app:update-rules` が置き換える） |
