# テストの実行

## 実行

**ルートの `npm test` は先に `shared` を建てる。** 範囲を絞るコマンドは建てないので、
`shared` を変えた直後は先に `npm run build` を通す（`@app/shared` が解決できずに落ちる）。

| 範囲 | コマンド |
|:--|:--|
| すべて | `npm test` |
| 1 つのパッケージ | `npm run test -w <client\|server\|shared>` |
| ファイルを指定 | `npm exec -w <パッケージ> -- vitest run <パス>` |
| 変更に関係するものだけ | `npm exec -w <パッケージ> -- vitest related --run <変更ファイル>` |

引数（`$ARGUMENTS`）にファイルやパターンがあればそれを対象にする。無ければ、
**直前に変更したパッケージ**から始める（全部を毎回流さない）。

## DB を使うテスト

- 既定は PGlite。**外部の PostgreSQL は不要**で、そのまま走る
- 実 PostgreSQL でしか確認できないものは、接続先を渡す環境変数を足してから走らせる（名前は `docs/env.md` に書く）
- テストが「マイグレーションが当たっていない」で落ちたら `/shinnn-app:db-migrate`

## 落ちたときの判断

**実装が正か、テストが正かを先に決める。** ここを飛ばして直すと、間違った挙動をテストで固定してしまう。

判断は `.claude/rules/testing.md` の「何をテストするか」の表に従う（読み込まれていなければファイルを開いて読む）。
`skip` するときの手順も同じ規約にある。テストを通すためだけの分岐を入れたくなったら、それは実装が間違っている合図。

## 報告

```
テスト: 成功 N / 失敗 N / スキップ N
失敗の場合: テスト名 - 期待 と 実際
```
