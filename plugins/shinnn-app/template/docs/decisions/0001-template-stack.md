# 0001. このテンプレートの技術選定

- 状態: 決定
- 日付: 2026-09-06

> **設計判断の記録（ADR）とは**
> 「なぜそう決めたか」を 1 件 1 ファイルで残す文書です。決めた本人がいなくなっても、
> 後から来た人が「これは変えてよい判断か」を自分で判断できるようにするために書きます。
> Issue ではなくファイルに置くのは、コードと一緒にバージョン管理したいからです。
> 新しい判断をするたびに、`0002-<内容>.md` のように番号を増やして足していきます。
> **決めたことを後から書き換えず**、覆すときは新しいファイルを作り、この状態を「置き換え済み」にします。

## 背景

このテンプレートは、開発に慣れていない担当者が Claude Code でアプリを作り、
できあがったものをシン株式会社が保守・機能追加できる状態に保つためのものです。
そのため技術の選定では、次を重く見ました。

1. **AI がよく知っていること** — 学習データに実例が多い技術ほど、生成されるコードの質が安定します
2. **長く保守されること** — 数年後にライセンス変更や更新停止が起きにくいこと
3. **層が浅いこと** — 1 つの機能を直すときに開くファイルが少ないこと
4. **配布できること** — 顧客がそのまま使える形（商用ライセンスの制約がないこと）

## 決めたこと

| 領域           | 採用                                                                     | 理由                                                                                                                                                                 |
| :------------- | :----------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| サーバー       | Express 5 / Node.js 24 LTS / TypeScript ESM                              | シン株式会社の既存製品と同じ。AI の習熟度が最も高い。OpenJS Foundation の保守体制と脆弱性対応の窓口が明文化されている。Node.js の版は [0003](./0003-node-version.md) |
| DB             | PostgreSQL 16 + Drizzle ORM                                              | 顧客案件で最も使われる。Drizzle は Apache-2.0 で、TypeScript のスキーマ定義からマイグレーションを生成でき、ネストしたトランザクションに対応する                      |
| API 定義       | `shared` の zod スキーマ + 自作の小さなヘルパー                          | 画面とサーバーが同じ定義を参照する。既製のライブラリは更新が止まっている例が多いので、100 行程度の自作にした                                                         |
| 画面           | Angular（standalone / signals）+ Angular Material + CDK + Tailwind CSS 4 | Material は MIT で Google が Angular と同時にリリースする。AI の習熟度も最大                                                                                         |
| テスト         | Vitest。サーバーは実際に HTTP を叩く。DB は PGlite                       | 追加のインストールなしで、本番と同じ経路を検証できる                                                                                                                 |
| パッケージ管理 | npm workspaces（shared / server / client）                               | 3 つのパッケージをまとめて扱える。npm は Node.js に同梱されるので追加で入れるものがない。選定の理由は [0002](./0002-package-manager.md)                              |

## 採らなかったもの

| 候補                          | 採らなかった理由                                                                                                                           |
| :---------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------- |
| PrimeNG                       | 22 以降が商用ライセンスに変わり、**テンプレートとして配布する用途は別途 OEM ライセンスが必要**になった。MIT の 21 系は Angular 21 で止まる |
| Prisma                        | 7 系で ESM 専用化など破壊的な変更が続いており、追従の負担が大きい                                                                          |
| ts-rest / zodios              | API 定義の共有ライブラリ。前者は安定版が Express 4 / zod 3 のみ、後者は 2023 年に更新が止まった                                            |
| NestJS                        | 層が深く、1 つの機能を足すのに触るファイルが多い。開発に慣れていない担当者には向かない                                                     |
| NgRx などのグローバル状態管理 | 画面の状態がどこから変わるかを追えなくなる。signals で足りる                                                                               |
| MongoDB                       | 当面の顧客案件は関係データベースが前提。必要になったら別の判断として記録する                                                               |

## 結果

- 1 つの機能を足すときに触るのは、`shared/src/api/` → `server/src/api|service|db/` →
  `client/src/app/features/` の 3 か所です
- API 定義を変えると、直し忘れた側が**ビルドエラーになります**
- 開発に慣れていない担当者でも、`npm install` / `npm run dev` / `npm test` の 3 つで動かせます

## 見直す時期

- Angular はおよそ半年ごとに新しい版が出るため、四半期ごとにテンプレートを追従させます
- API 定義のヘルパーは自作なので、既製品（oRPC など）が安定したら乗り換えを検討します
