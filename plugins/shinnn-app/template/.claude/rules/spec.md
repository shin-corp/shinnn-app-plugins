# 仕様書の規約

## 書き方

- 表のセルには、1 つのことを 1〜2 文で書く
- 画面の表（4. 画面）の「何ができるか」には、使う人から見てできることだけを書く
- 状態ごとの表示のような、残したい振る舞いは受入条件にする
- 受入条件の場合分けの細部は、テストに書く
- 仕様書は 150KB までにする（検査: CI。`docs/仕様書.md` だけを見る。超えたときに注意を出すだけで、止めない）
- 表のセルは 1,000 文字までにする（検査: CI。`docs/仕様書.md` だけを見る。超えたときに注意を出すだけで、止めない）
- 表は、列の幅を空白でそろえずに書いてよい（コミットのときに prettier が整える。`docs/仕様書.md` と `docs/移植対応表.md` では、1 行の幅が 120 桁（全角の文字は 2 桁）を超える表を詰める）

## 受入条件の立て方

- 受入条件は、使う人から見える振る舞い 1 つに 1 つ立てる
- 同じ 1 件を扱う操作（例: id を指定した取得・更新・削除と、無い id で 404）は、1 つの受入条件にまとめてよい
- 画面の 3 状態（読み込み中・0 件・失敗）は、1 つの受入条件にまとめてよい

## 理由

この規約の理由は `.claude/rules-why/spec.md` にあります。決まりに当てはまるかを迷ったときに読みます。
