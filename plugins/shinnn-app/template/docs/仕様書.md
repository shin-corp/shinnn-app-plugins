## 5. データ

| 名前 | 項目                                                     | 誰が見られて誰が変えられるか                       | 説明                                                               |
| :--- | :------------------------------------------------------- | :------------------------------------------------- | :----------------------------------------------------------------- |
| item | id / name / description / status / createdAt / updatedAt | 作った利用者（持ち主）だけ。他の利用者には見えない | サンプルとして同梱している題材。自分のアプリのデータに置き換えます |

- `name` は 1〜100 文字、必須。同じ持ち主の中で重複できない（他の利用者の item とは同じ名前でよい）
- `description` は 1000 文字まで、省略可
- `status` は `draft`（下書き）/ `active`（有効）/ `archived`（保管）のいずれか

<!-- 項目の細かい制約は shared/src/api/ の zod スキーマが正です。ここには意味を書きます。

     ここが空のままだと、ログインした人なら誰でも他人のデータを読める作りになりがちです。 -->

## 6. 受入条件（AC-n）

AC は Acceptance Criteria（受入条件）の略です。`AC-n` の `n` は通し番号で、テスト名の先頭にも同じ `AC-n` を書きます。

**「これが確認できたら完成」と言える条件**を、番号を振って書きます。
1 条件につきテストを 1 つ以上作ります。CI が対応を確認します（`scripts/check-ac-coverage.mjs`）。

| ID    | 条件                                                                                                                        | 確認方法                                   |
| :---- | :-------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------- |
| AC-1  | item の一覧が name の順に返る。1 ページの既定は 20 件で、`limit` と `offset` で範囲を変えられる。0 件のときは空の一覧を返す | `server/tests/items.test.ts` の `AC-1 …`   |
| AC-2  | id を指定すると item を 1 件取得できる                                                                                      | `server/tests/items.test.ts` の `AC-2 …`   |
| AC-3  | item を作成すると 201 で作成した内容が返る。`status` を省略すると `draft` になる                                            | `server/tests/items.test.ts` の `AC-3 …`   |
| AC-4  | item を更新すると、渡した項目だけが書き換わる                                                                               | `server/tests/items.test.ts` の `AC-4 …`   |
| AC-5  | item を削除すると 204 が返り、その後は取得できない                                                                          | `server/tests/items.test.ts` の `AC-5 …`   |
| AC-6  | トークンが無い・受け取り手が違う・期限切れ・期限そのものが無い要求は 401 を返す                                             | `server/tests/items.test.ts` の `AC-6 …`   |
| AC-7  | 入力が形式に合わないとき（name が空、id が uuid でない、件数が上限超え、本文が JSON でない）は 400 と理由を返す             | `server/tests/items.test.ts` の `AC-7 …`   |
| AC-8  | 自分の既にある item と同じ name では作成も更新もできず、409 を返す。他の利用者の item と同じ name ならできる                | `server/tests/items.test.ts` の `AC-8 …`   |
| AC-9  | 存在しない id の取得・更新・削除は 404 を返す                                                                               | `server/tests/items.test.ts` の `AC-9 …`   |
| AC-10 | 稼働確認（`/health`）は認証なしで 200 を返し、どのルートにも当たらない URL は 404 を返す                                    | `server/tests/health.test.ts` の `AC-10 …` |
| AC-11 | 他の利用者の item は一覧と件数に入らず、id を指定した取得・更新・削除は 404 を返す                                          | `server/tests/items.test.ts` の `AC-11 …`  |

     「使いやすいこと」のような、確認できない書き方にしないでください。 -->
