# コードレビュー

変更差分を 3 つの観点から同時にレビューし、重要度別に統合して報告する。
**指摘するだけで、直すのは別。** 直す判断は人と、そのあとの作業に任せる。

## 1. レビュー対象を決める

| 状況 | 対象 |
|:--|:--|
| PR を出す前 | `git diff origin/main...HEAD` |
| 未コミットの変更がある | `git diff HEAD` と `git diff --cached` |
| どちらも無い | `git diff HEAD~1` |

ファイル一覧を先に示し、これでよいか確認する。日本語のファイル名が含まれるので、
`git -c core.quotepath=false diff --name-only` を使う。

## 2. 決着済みの前提を集める

エージェントは毎回まっさらな状態で起動するので、既に決着した論点も渡さなければまた出てくる。
起動の前に次を集める。

| 集める先 | 取るもの |
|:--|:--|
| PR があれば `gh pr view --json body` | 本文の「見送った指摘」と、その理由 |
| `docs/decisions/` | 変更したファイルに関係するもの |

**「引き継ぎメモ」Issue は読まない。** レビューのたびに全文を読むと重く、決着していない話も混ざる。
読むのは `retro` の担当。

**見つからなければ「無し」として進む。** 無いことを理由に止めない（`gh` が使えない環境もある）。
集めたものは「決着済みの前提」として 1 つにまとめ、3 体すべてに同じものを渡す。

## 3. 3 つのエージェントを同時に起動する

Task ツールで、**1 つのメッセージで 3 体まとめて**起動する。各エージェントには、変更ファイルの一覧と差分、
および手順 2 の「決着済みの前提」を渡す。

| エージェント | 担当 |
|:--|:--|
| `correctness-reviewer` | バグ・ロジック・信頼性・不要コード |
| `security-reviewer` | セキュリティ・パフォーマンス |
| `conventions-reviewer` | 配置と依存・規約・一貫性・可読性 |

エージェントには次を必ず伝える。

- 変更ファイルだけでなく、**import している依存先**と、**同じディレクトリの同種ファイル**も読むこと
- 指摘には Critical / Warning / Info を付けること
- **推測で指摘しないこと**。実際にファイルを読んで確かめた事実だけを挙げる
- **決着済みの前提に反する指摘はしないこと**。前提そのものの再検討が要ると判断した場合だけ、
  Info として 1 行書く（同じ論点を何度も出さない）
- エージェントが使えるのは読み取りの道具（Read / Grep / Glob）だけで、ファイルの作成・変更もコマンドの実行もできない。
  **読むのに必要な情報はこの手順で渡す**（変更ファイルの一覧、差分、決着済みの前提）

## 4. 統合して報告する

3 体の結果を受け取り、重複を除いて重要度順に並べる。

```
## レビュー結果

### 対象
変更ファイル N 件

### Critical（直さないと出せない）
#### [観点] タイトル
- ファイル: path/to/file.ts:12
- 何が: 起きること
- なぜ: なぜ重大か
- 直し方: 具体的に

### Warning（直したほうがよい）
### Info（参考）

### サマリー
| 重要度 | 件数 |
| Critical | N |
| Warning | N |
| Info | N |
```

**良かった点を 1 つ必ず書く。** 指摘だけを並べると、何が正しい書き方なのかが伝わらない。
Info は 5 件までに絞る（多いほど読まれない）。

## 重要度の基準

| 重要度 | 基準 | 例 |
|:--|:--|:--|
| **Critical** | データを壊す・受入条件を満たさなくなる・秘密が漏れる | 層をまたいだ参照、`await` 漏れ、トランザクション境界の誤りで中間状態が残る、認証情報のハードコード、人が入れたデータを消す |
| **Warning** | 仕様と食い違う・誤った値を残す・テストが実際には検証していない | 仕様書との食い違い、競合で壊れる、実装と食い違うコメント、失敗しても通るテスト、規約違反、N+1 |
| **Info** | 情報・好みの範囲 | 命名の提案、代替の書き方 |

**迷ったら 1 段階重く見る。** 「動くが誤った値を残す」は Warning ではなく Critical。
**ファイルの行数は指摘しない**（行数の上限は規約に無い）。
