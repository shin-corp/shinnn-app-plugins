# CLAUDE.md

このリポジトリで作業するときの全体方針です。決まりの細かい中身は、規約（`.claude/rules/`。触るファイルに合わせて読み込まれる）と、`client/`・`server/` の CLAUDE.md にあります。**優先順位: `docs/仕様書.md` > CLAUDE.md > `.claude/rules/`。** 食い違ったら下位を直します。

**ここと規約に書いていない書き方と作り方は、既存のコードに揃えたうえで、自分で判断して進めてよい。** 判断が分かれた点は、PR 本文の「規約で迷った点」に書く。仕様で決まっていないことの扱いは、規約 `git-workflow.md` と `/shinnn-app:feature` に従う。

## 進め方

- 頼まれた変更は、文言 1 つの直しでも、`/shinnn-app:feature` で Issue → ブランチ → PR の順に進める（`main` で直接編集しない。決まりは規約 `git-workflow.md`）
- `.shinnn/setup.json` の `mergePolicy` が `auto-merge` なら（`setupCompletedAt` が `null` のときを除く）、利用者はマージまで任せている。確認を挟まずに作りきる（規約 `git-workflow.md` の「`auto-merge` のとき」）
- 引き継ぎの注意・シン株式会社への要望・規約で迷った点・CI で確かめていないマージの置き場所は、pin した「引き継ぎメモ」Issue の同じ名前の見出しの下（見出しが無ければ足す）
- 依存の脆弱性の勧告（CI の「依存の脆弱性」の失敗や注記）を直すときは、Issue とブランチを `/shinnn-app:check` の「`npm audit` で勧告が出たとき」で決める

## 構成と技術

| 場所       | 中身                                                                                               |
| :--------- | :------------------------------------------------------------------------------------------------- |
| `shared/`  | 画面とサーバーが共有する **API 定義**（zod 4 + `defineRoute()`）。業務ロジックと DB 依存は置かない |
| `server/`  | Express 5 / Node.js 24 / TypeScript ESM。PostgreSQL 16 + Drizzle ORM（テストは PGlite）            |
| `client/`  | Angular（standalone / signals / zoneless）+ Angular Material + CDK + Tailwind CSS 4                |
| `docs/`    | 仕様書・環境変数・設計判断の記録（`docs/decisions/`）・自動テストで確かめられないものの確認結果    |
| `scripts/` | CI と `/shinnn-app:check` が使う確認のスクリプト                                                   |

**API 定義**は、画面とサーバーがやり取りするデータの形（URL・入力・出力）を、`shared` に 1 か所だけ書いたものです。`client` と `server` は互いのソースを import せず、この定義だけを共有します。テストは Vitest（`*.test.ts`）です。パッケージは npm workspaces で分けています。

**使わないもの**: NestJS / NgRx / GraphQL / ORM の抽象化層の追加 / 独自 CSS

**車輪の再発明をしない。** このアプリに固有でない処理（CSV・ZIP の読み書き、日付の計算、グラフなどの画面の部品、メールの送信など）は、自前で書く前に、Node.js とブラウザに組み込みの機能・既に入っている依存・広く使われているライブラリの順に探して使う。入れてよいライブラリの条件は規約 `libraries.md` に、探し方は `/shinnn-app:feature` の「ライブラリを探す」にある。

**費用が発生するものは入れない。** 有償・商用ライセンスのライブラリと、利用料が発生する外部サービスの SDK は、要ると分かった時点で実装を止める。そのうえで、「引き継ぎメモ」Issue の「シン株式会社への要望」に理由と代替案を書いて判断を待つ。

## コマンド

`npm install` → `npm run dev`。確かめるのは `npm run check` と `npm test` です。ルートのこの 4 つは `shared` のビルドを先に済ませるので、クローンの直後でもそのまま動きます。

終了コードを出すときは、`npm test; echo "exit=$?"` のように文字と一緒に出す（`echo "$?"` のように変数だけを出すと、毎回確認が出る）。

## 共通方針

- 利用者への返答・コメント・PR 本文・文書は日本語で書く（コミットメッセージは規約 `git-workflow.md`）。識別子は英語、画面の文言は日本語にする
- コメントに、レビュー対応の経緯を書かない
- 実装を変えたら、周辺のコメントと JSDoc も直す
- 知見を足すときは、まず既存の該当箇所を直す。1 つの事実は 1 か所にだけ書く
- `.claude/settings.json` は標準なので、`/shinnn-app:update-rules` が丸ごと置き換える。変えたいことは「シン株式会社への要望」に書く
- 個人の設定は `.claude/settings.local.json`、個人のメモは `CLAUDE.local.md` に書く（どちらも git に入らない）
- このアプリだけの手順は、`.claude/skills/<名前>/SKILL.md` に置く（どのアプリでも要る手順は、シン株式会社がプラグインで配る）

## このアプリだけの決まり

このアプリだけの決まりは、`docs/仕様書.md` の「7. Claude 向けのルール」に書く（AI を使うなら、呼んでよい場所と出力の扱いも書く）。
